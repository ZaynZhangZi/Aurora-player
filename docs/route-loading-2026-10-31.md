# 2026-10-31 路由加载优化

## 改动

- 发布本地已有的主页面缓存修正：保留首页、发现、音乐库三个页面；导航悬停、键盘聚焦及按下时预热页面代码，和空闲预热共享同一任务。
- 首页歌单、发现页、搜索结果、音乐库及艺人链接接入详情预取。悬停或聚焦停留120毫秒后开始，离开或项目变化会取消未启动的任务；按下时立即预取。最多同时预热两个详情、等待队列保留最近四项，隐藏页、省流量和2G不做推测预取。
- 详情读取使用20秒、最多24项的内存缓存，合并进行中的请求，每个消费者独立取消；只有所有消费者都退出才中止共享请求。缓存结果分别复制，避免组件修改影响下次打开。
- 缓存按账号和Cookie切换清理。歌单编辑、收藏和歌曲排序成功后使相应详情失效。缓存读取前后都校验维护规则，推测预取先检查页面开关，不执行任何写操作。
- 歌手页先读取基础资料和热门歌曲；全部歌曲、专辑和MV等待首屏接口完成，相关区域接近视口并且页面在前台时再利用空闲时间读取。“全部歌曲”按钮仍可主动触发加载，切换歌手或离开中止旧请求。
- 歌单复用详情接口已有的歌曲前缀，只请求缺少的页，每批最多两页、批次间让出空闲时间，最终仍组装完整且顺序一致的曲目列表。
- 主页面和详情浮层使用浏览器原生过渡动画，保持Hero封面飞入、焦点恢复和滚动锁。GSAP与Motion分别拆包，入口不再静态依赖整个动画包；可视化引擎继续独立按需加载。
- 同时整理原有图片加载不阻塞内容、图片取色缩略图、后台媒体停止视觉工作和播放器进度订阅优化。

## 测量

本机生产构建，Chrome无头模式，1440×1000，CPU降速4倍、网络延迟40毫秒、下载1,500,000 bytes/s，禁用HTTP缓存。每项运行3次，下表取中位数。API使用固定模拟响应；详情API人为延迟500毫秒。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 搜索页首次解除开屏阻挡 | 1121 ms | 1112 ms |
| 当时已完成JS解码大小 | 776 KiB | 591 KiB |
| 悬停后点击专辑，到详情标题出现 | 749 ms | 183 ms |
| 返回后再次打开同一专辑 | 620 ms | 107 ms |
| 上述两次打开的专辑API请求数 | 2 | 1（点击前预取） |
| 入口静态JS依赖gzip总量 | 173.8 KiB | 87.6 KiB |

首次详情点击前，两版均模拟悬停900毫秒。优化后的等待被提前到悬停期间；数据不命中缓存、触屏没有提前停留或真实API更慢时，不会保证183毫秒。再次访问在20秒缓存有效期内。冷启动解除开屏时间此次没有明显变化，主要收益是更少的JS下载、详情点击等待和重复访问。

这些是固定模拟条件下的本地观测，不是线上全体用户的速度承诺，也不是整个应用的包体大小。入口统计只计HTML入口的静态JS依赖闭包；可选歌词、可视化和路由页面另计。

## 验证方式

- `npm test`：完整前台回归；`tests/detail-loading.test.mjs`额外覆盖请求合并、独立取消、失败重试、TTL/LRU、结果隔离、账号切换、维护检查、缺失曲目补齐、可见性加载和预取排队。
- `npm run build`：生产构建。
- `tests/.route-speed-browser.mjs`：用保存的优化前生产构建作对比，`ROUTE_BASELINE_DIST`指定基线dist；结果写入`ROUTE_BENCHMARK_OUTPUT`。模拟API不连接真实账号或数据库。
- `tests/.maintenance-browser.mjs`：检查全部页面直链、功能关闭后的持续拦截、恢复、详情浮层和后台自动保存。
